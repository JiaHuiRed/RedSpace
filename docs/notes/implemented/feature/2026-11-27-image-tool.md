# 图片是工作区文件，`image` 不属于某个聊天模型

状态:implemented

## 问题

旧 `image` 工具在图片 API 到期时随供应商一起退役（`03c285ce`）。替代接口可用后，用户仍需离开 RedSpace 生成图片，再搬回原来的对话。工具是否存在、用哪个账户画图、成品在哪里，是三个不同的问题。

## 决策

- Chat 和 Code 使用同一个内置工具，不需要搜索或激活。没配置后端仍展示工具，在执行时说明如何配置。只读 agent、会话权限和显式关闭的工具不因此获得授权。
- `image_generation` 选择图片供应商、请求型号和认证方式，不读当前对话模型。未配置时只自动使用唯一已登录且声明了图像能力的 OAuth 插件；没有或有多个都不猜。兼容 Images API 的供应商须显式选择，只取它自己的地址和凭据。订阅失败、认证变化、供应商拒绝都不改走另一种计费方式。其他订阅可实现插件的 `auth.image`，不用重写工具或客户端。
- 给 `image` 的本地源文件才会随编辑请求发送。先检查来源、目标路径和权限，再发生成请求；只创建新文件，不覆盖，也不自动下载响应里的外部链接。源图和结果分别不超过 20 MiB。用实际文件头识别 PNG、JPEG、WebP。
- 默认在本次实例的 `.redcode/temp/` 另存。工具结果只带路径和必要元数据，不返回图片附件。TUI 显示路径；GUI 只从本轮 **completed** 的 `image` 记录收集工作区内的产物，点击后才让文件服务读图，不扫描目录、不从聊天文字猜路径。

## 备选与否决理由

- **整体还原旧实现**：会带回旧供应商的 API key 读取方式、已经被迁移程序清理的 `config.image`，还会把 2 MiB 以下的原图作为 data URL 写回工具消息。
- **把图像模型放进聊天模型选择器**：切换聊天上下文不是用户要画图的含义，而且不同供应商的订阅能力不等价。模型输出的调用参数不能改图片后端的地址或认证方式。

## 模型可见四问

1. 旧工具表没有 `image`；现在有一个固定函数：用 `prompt` 生成，用可选 `image` 路径编辑，结果是新文件的路径。没有新增系统提示、记忆或每轮的供应商清单。
2. 用现有 `ToolJsonSchema.fromTool` 序列化单项 `{type,name,description,parameters}`：907 UTF-8 字节，按项目诊断口径约 227 token。是未做供应商变换的单项估算，不是服务端计费数据。
3. 发布后工具表从首个变化项起一次性重建缓存；启用了 `run_code` 的会话也会更新其可调用工具声明。后续生成、编辑、切换图片型号不改变这份静态工具表。图像输入只属于图片后端，不追加到聊天模型的下一轮。
4. 提示词最多 8192 字符（长提示可超过 1K token，是用户要交给图片后端的内容），每个文件路径最多 4096 字符，型号最多 256 字符；响应流与解码后图片分别有硬上限。正常工具输出是固定前缀加成品路径，没有 base64。

## 验收证据

- 本机 HTTP 测试文本供应商收到了新 Code、新伙伴主 Chat 的第一轮请求；都没有图片后端配置或工具发现记录。用户只说「Reply with OK.」，两个请求都含 `image`。
- 真实订阅的隔离会话里，自然语言生成后续改橘猫围巾。两张 1254 × 1254 PNG 均可解码，来源文件哈希未变。文件分别为 1,202,908 和 1,278,350 字节，而数据库里的两个工具 part 只有 1,050 和 1,090 字节，无附件。初次验收还发现默认请求型号误写，已改为 Codex 使用的 `gpt-image-2` 并加断言；回包没有给出实际执行的快照型号。
- 兼容 API 以隔离 HTTP 服务验生成和 multipart 改图；第三方订阅以测试插件验选择和回调，不冒充其他付费账户的线上实测。Chromium 验成果卡点击打开；真实文件服务对两张 `.redcode/temp/` 文件均逐字节读回原图。编译版 TUI 在独立终端重开这段历史，生成与编辑两条工具行都显示完整路径。
