# 可编辑的视觉草稿

从当前对话接着做，不要求用户重述需求或喊出技能名。没有上下文才问想先看哪一块。明确要打开已有页面或直接修改产品时，按原意做，不额外加原型环节。

1. **先给一份能看的草稿。** 项目根目录有 `docs/` 就用 `docs/Visual/`，否则用根目录的 `Visual/`。目录不存在就先创建，再在里面编写或续改可双击打开的单文件 `<主题>.html`。沿用现有界面的内容和布局，只模拟这次要决定的部分；用示例数据，不接业务服务，不改正式代码。
2. **把选择做在页面上。** 栏宽待定，就给一个能直接调的栏宽，旁边显示当前像素值；TUI 排版用行、列，文案待定就让文字就地可改。只给这次用得到的控件。提供「导出当前 HTML」，让改过的值和文字写进文件，重新打开仍是所见的版本，不只留在浏览器里。
3. **交给用户看。** 确认能打开、能调、导出重开不丢改动，就给文件链接，点明哪里可调。用户说「开个网页」时，能在用户可见的浏览器打开就直接打开。用户也可以只提意见，由你改同一份草稿；动手前重读文件，保留对方已改的部分。
4. **以定稿为准。** 用户说「照这版做」，或已约好确认后开工并得到确认，就重读用户保存或导出的那份 HTML，按它实施，不再让用户复述参数。若一开始就给了定稿，直接走这一步。验证实现与定稿相符、受影响的交互可用，不再替用户评一次审美。
