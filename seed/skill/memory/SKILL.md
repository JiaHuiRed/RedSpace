# 工程记忆

## 写入前

删掉这句，下次会在哪个场景做错哪一步？`MEMORY.md` 留会改变续接或行动的信息。规则、校验已覆盖的内容不重复写；场景相关的细节进正文。同坑复发两次标出防复发的机制缺口，三次及以上用机器门禁拦，记忆留入口。

按字符数（UTF-16，不按字节或行数）判断是否先剪：项目 `.redcode/MEMORY.md` 超过 **4800**，全局 `~/.redcode/MEMORY.md` 超过 **8800**。

## 更新项目记忆

核对当前状态、近期 Git 提交和已有文档，检查标题下的五区并按主题更新：

1. **引语**：一行说明怎么用本页、到哪里查正文。
2. **当前进度**：最近几项影响续接的进展、正在做什么和从哪接。已提交的旧进度查 Git，待办和未入 Git 的状态放 `.redcode/docs/`。
3. **项目入口与约定**：直接写任务要用的项目路径、工具入口、配置优先级或约束。
4. **教训索引**：一条写明什么场景要警惕、已知原因、下一步和正文路径。用动手前能认出的触发条件。
5. **新增暂存**：只放尚未归位的教训，归位后移出；空时写「暂无」。

先写或更新完整教训正文，再在同一批更新索引。复用 `.redcode/docs/` 或已有权威文档；公开决策沿用仓库的 `docs/notes/` 约定。旧格式只在更新当前工作区时迁移：先安顿仍有效的待办和独有教训，核对文档都有索引或进度入口，再按五区归位。

## 独立教训双写

没有权威文档且值得独立召回时，将全文存入 `~/.redcode/supermemory.db` 的 `memories`（`source='manual'`），并写对应索引。已有正文只更新文档和索引。

- **全局**（`project='global'`）：用 `bun ~/.redcode/scripts/next-memory-id.mjs` 查本机库最大号再加一，落库前确认 `WHERE project='global' AND content LIKE '#NN %'` 无匹配。全文首行 `#NN 标题（YYMMDD）`，索引同号；编号不复用、不重排。新增可先放全局暂存区。
- **项目**（`project=<项目名>`）：全文首行 `[项目名·踩坑|决策|技法] 标题（YYMMDD）`，索引附可查库的标题，不另编号。
- 全局编号用 `bun ~/.redcode/scripts/check-memory-dualwrite.mjs` 核对；项目条目按项目和标题查全文。库写入后用 `bun ~/.redcode/scripts/export-memory-backup.mjs` 做本机滚动备份。

独立库条目用 `/recall <关键词>` 或直接查库。

## 整理与审计索引

- **日常剪枝**：通读 MEMORY，合并同类内容，保留触发条件、实际操作和来源。旧进度有 Git 记录就不转抄；仍有用但 Git 无法还原的旧状态归 `.redcode/MEMORY-archive.md`，不进库。
- **移出索引**：逐条读正文，确认已重复、失效（含不再适用的旧模型提醒）或不必开局知道，再移出；先核对文档或库中仍可找回，正文不删。低频但动手前必须知道的教训，仍留一句能触发查阅的索引。
- **验证**：项目核对五区、文档路径和待办去向；全局跑双写核对，库中有全文但无索引不算失败。两层均量字符数；大幅迁移后用新会话验证代表性问题能找到正文。

## 清理库正文（仅用户明确要求）

逐条看全文，核对保留来源和所有索引引用；无法确认的先留。留独立的本机恢复备份，列出拟删的 ID、标题、理由和替代来源，取得确认后才按清单删除。完成后核对实际删除集合、保留正文、FTS 召回和索引；不重编号。
